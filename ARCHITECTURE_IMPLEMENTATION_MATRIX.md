# VAT-MSA Architecture Implementation Matrix

**Evidence date:** 2026-08-25
**Repository scope:** executable controlled pilot and production-oriented application foundation  
**Governing architecture:** `08-enterprise-architecture/` and its approval gate

This matrix is the truthful completion record for the approved architecture. It separates working repository capabilities from controls that require NamRA, ITAS, legal, security, provider or infrastructure authority. A disabled boundary is an implemented safety control, not a simulated external service.

## Status vocabulary

- **VERIFIED PILOT** — executable end-to-end behavior is implemented and has automated or runtime evidence.
- **CONTROLLED FOUNDATION** — the tenant-scoped model, policy, data and read/workflow surface exist, but some lifecycle commands remain phased.
- **DISABLED PENDING AUTHORITY** — an adapter or state machine exists and explicitly refuses legal/financial effect until an approved contract, credential or rule set is supplied.
- **ARCHITECTURE / PRODUCTION EVIDENCE** — design artifacts exist, but completion can only be demonstrated in the selected national production environment.

## Verified release evidence

The canonical release gate passed on 2026-08-25:

- ESLint and TypeScript completed without errors.
- 180 unit/security/policy/route tests passed across sixteen test files. `tests/routes/module-1-access-control.test.ts` proves cross-organisation access, cross-role access, expired step-up and insufficient assurance level are provably rejected end-to-end through real route handlers — the first tests in this repo to exercise anything beyond pure domain functions. `tests/routes/module-2-vat-rule-engine.test.ts` proves the VAT rule engine's fail-closed enforcement end-to-end. `tests/routes/module-2-invoice-hardening.test.ts` fires the same invoice submission twice via `Promise.all` and proves it never double-posts (a genuine interleaved-async concurrency test, not a sequential one), and proves the P0 unidentified-buyer guarantee directly at the ledger level. `tests/routes/module-2-invoice-lifecycle.test.ts` proves invoice_number collisions are rejected, CancelInvoice's officer-only/narrow-eligibility lifecycle (denies the submitting taxpayer, reverses ledger entries, is idempotent, denies cancelling an invoice with an active correction), and that VerifyInvoice's public output surfaces correction and cancellation lineage. All run against a real SQLite engine (Node's built-in `node:sqlite`, wrapped to the `D1Database` shape) via test-only stand-ins for `cloudflare:workers` and `next/headers` (`tests/fakes/`, `tests/support/fake-d1.ts`) — necessary because both only resolve inside their real runtimes, which is why no route or repository code could be tested end-to-end before now.
- Heuristic secret scan passed and a CycloneDX SBOM was generated.
- The production build completed and exposed all application and API routes, including the new `GET /api/v1/me/access`, `POST /api/v1/registration-applications/:id/decision`, `POST /api/v1/organisations/:id/memberships`, `POST /api/v1/taxpayers/:id/suspension`, `GET`/`POST /api/v1/organisations/:id/branches` (+ `PATCH .../branches/:branchId`), `GET /api/v1/portals`, `GET /api/v1/counterparties/classification`, `GET /api/v1/licensing/entitlements`, `GET /api/v1/licensing/usage`, `POST /api/v1/licensing/state`, `POST /api/v1/licensing/upgrade`, `POST /api/v1/organisations/employees/:id/activation`, `GET`/`POST /api/v1/organisations/administrators`, `GET`/`POST /api/v1/organisations/capabilities`, `GET /api/v1/navigation/children`, `GET /api/v1/navigation/actions`, `POST /api/v1/navigation/preferences`, `GET`/`POST /api/v1/identity/links`, `GET /api/v1/identity/assurance`, `POST /api/v1/identity/links/:id/revocation`, `POST /api/v1/organisations/:id/invitations`, `POST /api/v1/invitations/claim`, `POST /api/v1/taxpayers/:id/identifiers/:identifierId/correction`, `POST /api/v1/taxpayers/:id/identifiers/verification`, `POST /api/v1/users/:id/suspension`, `POST /api/v1/users/:id/reactivation`, `POST /api/v1/access-grants/revocation`, `POST /api/v1/organisations/offboarding`, `GET`/`POST /api/v1/vat-rules`, `POST /api/v1/vat-rules/:id/approval`, `GET /api/v1/vat-rules/evaluate`, `GET /api/v1/invoices/:id/vat-explanation` and `POST /api/v1/invoices/:id/cancellation`.

## Production decision

The **approved implementable pilot scope is built and verified**. The system is **not authorised for statutory or national production**. Production approval remains blocked by the signed decisions and objective evidence listed in `08-enterprise-architecture/29-architecture-approval-gate.md` and `07-security-resilience/10-production-acceptance-gates.md`. No code change can legitimately substitute for those authorities, external contracts or infrastructure exercises.
