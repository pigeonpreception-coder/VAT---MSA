# VAT-MSA Architecture Implementation Matrix

**Evidence date:** 2026-08-25
**Repository scope:** executable controlled pilot and production-oriented application foundation  
**Governing architecture:** `08-enterprise-architecture/` and its approval gate

This matrix is the truthful completion record for the approved architecture. It separates working repository capabilities from controls that require NamRA, ITAS, legal, security, provider or infrastructure authority. A disabled boundary is an implemented safety control, not a simulated external service.

## Status vocabulary

- **VERIFIED PILOT** — executable end-to-end behavior is implemented and has automated or runtime evidence.
- **CONTROLLED FOUNDATION** — the tenant-scoped model, policy, data and read/workflow surface exist, but some lifecycle commands remain phased.
- **DISABLED PENDING AUTHORITY** — an adapter or state machine exists and explicitly refuses legal/financial effect until an approved contract, credential or rule set is supplied.
- **ARCHITECTURE / PRODUCTION EVIDENCE** — design artifacts exist, but completion can only be demonstrated in the selected national production environment.

The block has a logged exceptional-oversight override, not a dead end: supplying `override_reason` on the command lets the same actor proceed, but only if they hold the new `cases:override-sod` permission (granted only to `PILOT_ADMIN`/`NAMRA_SUPERVISOR`, never the ordinary officer roles being segregated from) — an override with the permission but no reason, or a reason without the permission, is still refused. ## Verified release evidence

The canonical release gate passed on 2026-08-25:

- ESLint and TypeScript completed without errors.
- 222 unit/security/policy/route tests passed across twenty test files. `tests/routes/module-3-compliance-obligations.test.ts` proves CreateObligation is national-scope-only, idempotent on retry and rejects a duplicate taxpayer/type/period under a different key, MarkSatisfied is idempotent both under the same key and under a fresh key against an already-satisfied obligation, and GetComplianceCentre reflects newly created obligations. `tests/routes/module-3-reconciliation.test.ts` proves RunMatch is officer-only, matches a cleanly certified invoice and is idempotent on retry, and — by directly corrupting a ledger row after a clean submission to simulate drift/tampering — proves it correctly raises an EXCEPTION, which Assign and ResolveException (idempotent) then carry through to resolution. The same file's GetWorkQueue suite seeds deterministic fixture exceptions of controlled severity/status/assignment/age and proves tenant scoping (a taxpayer-side actor never sees another taxpayer's exceptions; a national-scope NamRA actor sees all), every filter predicate, and pagination with a genuine `totalCount`. `tests/routes/module-1-access-control.test.ts` proves cross-organisation access, cross-role access, expired step-up and insufficient assurance level are provably rejected end-to-end through real route handlers — the first tests in this repo to exercise anything beyond pure domain functions. `tests/routes/module-2-vat-rule-engine.test.ts` proves the VAT rule engine's fail-closed enforcement end-to-end. `tests/routes/module-2-invoice-hardening.test.ts` fires the same invoice submission twice via `Promise.all` and proves it never double-posts (a genuine interleaved-async concurrency test, not a sequential one), and proves the P0 unidentified-buyer guarantee directly at the ledger level. `tests/routes/module-2-invoice-lifecycle.test.ts` proves invoice_number collisions are rejected, CancelInvoice's officer-only/narrow-eligibility lifecycle, and that VerifyInvoice's public output surfaces correction and cancellation lineage. `tests/routes/module-2-transaction-timeline.test.ts` proves GetTransactionTimeline returns the right chronological, correctly-linked events for a plain certification, a certification-plus-correction lineage reachable from either invoice id, and a certification-plus-cancellation lineage.
